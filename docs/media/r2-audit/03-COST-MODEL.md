# 03 — Cost model v2 (TASK 032.5)

Revised 2026-10-11. This replaces the 2026-10-10 version.

**Correction to v1.** The v1 model left out the metering infrastructure. It showed "$74.90/month at 2,000 Spaces" for R2 + Worker. That figure is **withdrawn**: it is not a forecast and must not be quoted as a future bill. Every figure below is an estimate, generated by `docs/media/r2-audit/cost_model.py`, which can be re-run when the assumptions change.

## What is verified and what is estimated

- **Vendor prices — VERIFIED.** Sources: 02-VENDOR-RESEARCH.md, plus two pages re-read on 2026-10-11:
  - Queues pricing: $0.40 per million operations; 1M included; 3 operations per message.
  - Durable Objects pricing: duration is billed only while the object is running, or idle but unable to hibernate. 128 MB is charged regardless of use.
- **Workload — ESTIMATE.** Bitrate 96 kbps, which is 0.72 MB per listening minute. The scenario parameters are shown in each table heading.
- **Cost basis.** Incremental monthly USD only. The Supabase Pro base fee ($25) is paid in every option and is excluded. Vercel function cost for issuing tokens or redirects is about the same in both architectures and is also excluded.
- **Current architecture compared against (verified in code, 01 §2).** `/api/media` checks access and returns a 307 to a freshly minted Supabase signed URL. Every playback start or reconnect gets a new URL, so the CDN, which caches per URL, rarely hits. "Supabase uncached" is therefore the realistic column; "cached" is the best case.
- **Actual usage today.** There are no paying customers. Production audio egress is far inside the free quotas. Real listening data does not exist yet, which is why metering starts observe-only (04 §M).

## Two metering designs

- **Design A — beacon to a per-tenant Durable Object.** Costed **conservatively**: 10 s of billable duration per beacon. Per the verified pricing, a request/response object that can hibernate is billed only while it runs, so real duration is likely far lower. A is the upper bound.
- **Design B — RECOMMENDED: no Durable Object.** Delivered bandwidth is recorded as one Workers Analytics Engine data point per range request; this is a cost metric, so sampling is acceptable. Listening usage comes from a cookieless client beacon (every 5 min and on pause/end). It goes to the Worker, then Cloudflare Queues, then an hourly batch into Supabase. 04 §F (v2) is updated to this design.

### Abuse scenarios (incremental $ per month, above quotas)

| Scenario | Cost |
|---|---:|
| Invalid/expired-token flood, 10M req/month (rejected before R2) | $9.20 |
| Invalid/expired-token flood, 100M req/month (rejected before R2) | $92.00 |
| Invalid/expired-token flood, 1,000M req/month (rejected before R2) | $920.00 |
| Valid-token tiny-range amplification, 10M req/month (R2 read each) | $13.00 |
| Valid-token tiny-range amplification, 100M req/month (R2 read each) | $130.00 |
| Leaked token re-downloading a 60-min file every 10 s for 10 min (60 GETs) | $0.00 |
| Same leaked-URL loop on Supabase (60 × 43 MB = 2.6 GB uncached egress) | $0.23 |
| Scraper pulling 1 TB of audio with valid tokens on Supabase (uncached) | $90.00 |
| Scraper pulling 1 TB with valid tokens via R2 (~23k GETs of 43 MB) | $0.02 |



Abuse notes:
- Requests with an invalid token are rejected in the Worker before any R2 operation, so they cost Worker requests and CPU only.
- A valid-token "tiny range" flood costs one R2 read per request. The per-token request cap (04 §D) limits it.
- On Supabase, abuse costs egress bytes. On R2 it costs operations only.

Design A (conservative Durable Object duration) gives about $0.32–0.41 per Space at Base. Both designs stay well below Supabase. Logs at 100% sampling are a visible cost at scale; reduce the sampling rate after the POC.

**The $75 figure is not a forecast.** At Base, R2 + Worker is about $239/month at 2,000 Spaces. The range across the three scenarios is about $18 to $1,409 per month. Real costs depend on measured request density and retries, which the POC measures (P-COST rows in 00).

## $5 add-on economics (marginal, one fully used add-on)

- +70,000 minutes is 50.4 GB of egress.
  - **Supabase uncached:** about $4.54, plus Stripe fees of about $0.65–0.85. This **loses money**.
  - **R2, Design B:** about 35,000 Class B reads plus Worker requests. That is about $0.02–0.05 once past the free quotas (more at High retry and seek rates, still under $0.25). **Viable.**
  - Neither figure includes support, refunds or Managed Payments fees (see the MP research).
- The add-on stays **not for sale** until metering is real (owner decision).

## Break-even

**Base scenario.** R2 is cheaper from about **10 Spaces**. At that point Supabase uncached is about $32/month against R2's fixed $5.

**Low scenario.** Supabase stays inside its free quotas up to about 25 Spaces. R2's fixed $5 makes it the more expensive option until about **50 Spaces**.

## Risks to these numbers

- Durable Object duration (Design A) is the largest cost uncertainty. Measure it in the POC (P-COST rows in 00 §POC).
- If the POC finds that Safari/iOS refetches far more often than modelled, R2 read and Worker request costs scale linearly. The High column already models twice the base retry rate.
- A Cloudflare budget alert notifies but does not cap spending (02 §G). Abuse is bounded by WAF rate limits, per-token request caps and rejecting invalid tokens before any R2 call (04 §D).
- B2 storage pricing is inconsistent between two Backblaze pages. The higher figure is used.
